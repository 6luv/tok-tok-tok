# PRD — 순간 시간 기록 iOS 앱

문서 버전: 0.1 / 작성일: 2026-10-31 / 상태: 구현용 초안

## 1. 목적

화면을 오래 보거나 글을 입력하지 않고, 사용자가 행동한 순간의 현재 시각을 로컬에 저장한다. 새벽에 잠깐 깬 순간, 버스에 탄 순간처럼 일상적인 사건을 나중에 확인한다. 수면 진단이나 자동 활동 감지 기능은 제공하지 않는다.

## 2. 확정 요구사항과 제안의 구분

확정: iPhone용 iOS 앱, App Store 배포, 간단한 시간 기록, 외부 액션 연결, 하루치 화면, 위에서부터 쌓이는 전체 폭 기록 목록(사용자 결정 2026-11-10, 기존 ‘하단부터 쌓기’에서 변경), 다크 기본, 로컬 저장, 사용자 지정 하루 경계, Claude Opus 5.5 구현 및 Codex Astra 검증 역할 분리.

이전 대화의 오전 6시 기본값 및 오후 11시 고정안은 채택하지 않는다. 최초 경계값은 미결정이며 사용자 설정으로 변경 가능해야 한다.

제안: Swift·SwiftUI·SwiftData, iOS 17 이상, 서버·계정·광고·분석 SDK 없는 MVP. 기술 버전은 실제 SDK와 배포 목표 확인 후 확정한다. 아래에서 ‘잠정’으로 표시한 내용은 QUESTIONS.md의 결정을 받기 전 제품 확정사항으로 홍보하지 않는다.

## 3. MVP 범위

| ID | 요구사항 | 완료 조건 |
|---|---|---|
| R01 | 앱 내 현재 시각 기록 | 한 번의 명시적 실행으로 저장 완료한 기록 한 건 생성 |
| R02 | 단축어 액션 | 매번 입력할 매개변수 없이 ‘현재 시간 기록’ 액션 실행 |
| R03 | 뒷면 탭 안내 | 사용자가 iOS 설정에서 두 번/세 번 탭에 단축어 연결 가능 |
| R04 | 하루 화면 | 선택한 기록일에 속한 블록만 표시 |
| R05 | 화면 표현 | 전체 콘텐츠 폭 기록 목록, 위쪽 정렬(사용자 결정 2026-11-10), 다크 기본; DESIGN.md 준수 |
| R06 | 하루 경계 설정 | 00:00~23:59의 시·분을 선택하고 재실행 후 유지 |
| R07 | 영속성 | 오프라인 저장 및 재실행 후 동일 기록 조회 |
| R08 | 실패 처리 | 저장 실패를 성공으로 알리지 않고 재시도 안내 |
| R09 | 접근성 | 큰 글씨·VoiceOver로 기록 버튼, 시간, 날짜를 이용 가능 |
| R10 | 배포 | 실기기 검증 및 App Store 제출 준비 항목 완료 |

외부 연결 화면은 지원 방식과 설정 방법을 안내한다. ‘뒷면 세 번 탭’ 선택만으로 시스템 매핑을 변경하거나 설정 완료 여부를 자동 확인하는 것으로 표현하지 않는다.

위젯, 잠금 화면 위젯, 액션 버튼, Siri, 제어 센터 컨트롤은 확장 후보이다. 각 OS·기종의 지원과 테스트가 확인된 항목만 제공한다. MVP 필수는 앱 내 기록, App Intent/단축어, 뒷면 탭 설정 안내이다.

통계, 자동 수면 분석, 타이머, 메모·태그, 클라우드 동기화, 구독은 기본 범위에 넣지 않는다. 이전 날짜 조회, 삭제, 내보내기, 두 기록 간 경과 시간은 QUESTIONS.md에서 결정한다. 하루 화면이라는 이유로 과거 데이터를 자동 삭제하지 않는다.

## 4. 기록 의미와 저장

현재 시각은 앱의 기록 처리 진입 또는 Intent 수행 시작 시 한 번 읽는다. 뒷면의 물리적 탭 시각을 직접 얻는다는 의미가 아니다. 시스템 전달 지연이 있을 수 있다. 저장 완료 전 성공 메시지나 성공 햅틱을 보내지 않는다.

권장 기록 필드: UUID, occurredAt(절대 시각), recordedTimeZoneID, recordedUTCOffsetSeconds, source(app/intent/unknown). 실제로 알 수 있는 실행 경로만 저장한다. 동일 Intent가 단축어·Siri·뒷면 탭에서 호출되면 뒷면 탭임을 추정하지 않는다.

사용자 설정에는 dayStartMinutes(0~1439), 설정 버전 및 경계 설정 완료 여부를 둔다. 문자열로 포맷한 시간을 원본으로 저장하지 않는다. 기록일은 원본 시각과 표시 정책에서 계산하며, 경계 변경만으로 원본 시간을 수정하지 않는다.

앱과 Intent는 동일한 저장 서비스와 스키마를 사용한다. SwiftData를 쓸 경우 영속 저장소로 구성하고 명시적 저장 결과를 확인한다. UI와 Intent의 동시 실행, 저장소 오류, 재실행 및 마이그레이션을 시험한다. CloudKit 동기화는 활성화하지 않는다. 로컬 저장과 OS 기기 백업은 별개이므로 ‘기기 밖으로 절대 나가지 않음’을 약속하지 않는다.

각 사용자 실행은 독립 기록이다. 짧은 간격의 다른 실행을 임의로 중복 제거하지 않는다. 내부 재시도는 동일 작업 ID를 유지할 수 있을 때 멱등성을 확보한다. OS가 별도 호출로 전달한 재실행까지 exactly-once를 보장하지 않는다.

## 5. 사용자 지정 하루 경계

설정값은 분 단위 로컬 시각이다. 기록일 구간은 [해당 날짜의 경계, 다음 날짜의 경계)이다. 경계와 정확히 같은 순간은 새 기록일에 포함한다. 종료를 23:59:59 같은 상수로 표현하지 않는다.

예: 사용자가 23:00을 선택한 경우 10/31 22:59:59는 10/30 기록일, 10/31 23:00은 10/31 기록일이다. 이는 예시이며 기본값 지정이 아니다. 00:00을 선택하면 일반 달력 날짜와 일치한다.

헤더의 기록일은 경계가 시작되는 달력 날짜로 표시한다. 블록의 작은 날짜는 각 기록의 실제 달력 날짜를 표시한다. 따라서 10/31 기록일 안에 11/01 날짜 블록이 존재할 수 있다.

잠정 정책: 현재 기기 시간대를 기준으로 조회하며, 경계 변경은 모든 기록의 표시 그룹에 즉시 반영한다. 여행·시간대 변경으로 표시 시간과 기록일이 달라질 수 있으므로 안내한다. 저장한 원래 시간대 정보는 보존한다. 이 정책은 Q02·Q03의 답에 따라 변경한다.

달력의 날짜 연산으로 경계를 계산한다. 86,400초를 더하거나 시각에서 경계 시간만큼 고정 초를 빼서 날짜를 만드는 방법은 사용하지 않는다. DST로 경계가 존재하지 않는 날은 그 이후 첫 유효 시각, 두 번 나타나는 날은 첫 번째 시각을 사용하는 정책을 잠정 채택한다. 실제 API 동작을 테스트해 이 규칙과 일치시킨다.

첫 경계 설정 UX는 미결정이다. 잠정 구현은 첫 실행에서 경계 선택·확인을 요구하며, 설정 전 Intent 호출은 앱에서 초기 설정을 마치라는 오류를 반환한다. 선택기 미리보기 값은 제품 기본값으로 취급하지 않는다. 이 과정에서 기록 요청을 몰래 버리거나 나중 시각으로 자동 저장하지 않는다.

## 6. iOS 실행 제약

Back Tap → 사용자가 연결한 Shortcut → 현재 시간 기록 App Intent → 로컬 저장 순서이다. 앱이 공개 API로 시스템 뒷면 탭을 직접 등록·가로채거나 손쉬운 사용 설정을 자동 변경하는 기능은 설계하지 않는다. 설정 안내는 Apple의 공식 경로를 사용한다. [S01]

앱을 전면에 열지 않는 실행을 목표로 한다. 실행 모드는 채택 SDK의 supportedModes 등 공식 API와 배포 대상의 호환성을 확인한다. openAppWhenRun만으로 모든 버전에 대한 실행 정책을 고정하지 않는다. [S02]

인증 정책이 잠금 상태 실행을 허용하더라도 실제 트리거 전달, OS 표시 UI, 저장소의 Data Protection 접근 가능성은 별개다. 화면 꺼짐·잠금·재부팅 후 최초 잠금 해제 전·사용자가 강제 종료한 상태에서의 성공을 일괄 보장하지 않는다. 전면 UI나 인증이 필요한 경우와 실패 경우를 실기기별로 기록한다. [S03, S04]

백그라운드에서의 햅틱·소리·배너 없는 동작도 보장하지 않는다. 시스템 알림이나 Siri 음성을 앱이 모두 제어할 수 있다고 가정하지 않는다. 데이터 보호를 낮추거나 임의의 백그라운드 모드를 추가해 제약을 우회하지 않는다.

## 7. 성공·실패 기준

사용자가 다시 앱을 열었을 때 저장 성공한 기록이 모두 나타나야 한다. UI는 즉시 처리 상태를 보이고 완료 결과를 반영한다. 성능 수치는 실제 기기 측정 후 정한다. 저장 실패·중복·누락을 숨기는 평균 성공률만으로 출시하지 않는다.

화면을 보지 않는 사용이 핵심이므로 실기기 상태별 지원 범위를 출시 전에 확정한다. 핵심 사용 환경에서 작동하지 않으면 버그 또는 제품 제약으로 명시하고, 요구사항 변경 없이 완료 처리하지 않는다.

## 8. 배포 및 문서 연결

테스트는 TEST_PLAN.md, 구현 지침은 CLAUDE.md, 독립 검증은 AGENTS.md, 미결정은 QUESTIONS.md, 실패와 재검증은 TROUBLESHOOTING.md를 따른다. Apple 자료 링크는 SOURCES.md에 모은다. App Store 승인 자체는 보장하지 않으며 실제 승인 전까지 배포 완료로 표현하지 않는다.
