## UI 및 접근성

빈 상태, 1건, 50건, 큰 글씨 최대 크기, 작은 화면, VoiceOver, 모션 감소를 확인한다. 전체 폭·위쪽 정렬·최신 기록 위치·날짜가 바뀌는 첫 행의 날짜 표시는 DESIGN.md와 대조한다. 외부 기록 도착 시 읽던 스크롤을 유지하고 새 기록 이동이 작동해야 한다. 시간 변경 적용·취소·저장 오류를 확인한다. 색상 대비는 실제 렌더링 색으로 측정한다.

## 실기기 실행 매트릭스

최소 지원 OS와 출시 검증 OS, 뒷면 탭 지원 실제 기기에서 수행한다. 각 칸에 성공 여부뿐 아니라 트리거 횟수, 저장 건수, 중복·누락, 시스템 배너·인증·앱 전면 전환, 체감 지연, 오류를 기록한다. 반복 시험은 최소 10회로 시작하고 실패가 있으면 조건을 분리해 재현한다. 이는 통계적 신뢰성 보장을 뜻하지 않는다.

| 상태 | 앱 내 버튼 | 단축어 직접 실행 | 뒷면 두 번/세 번 탭 |
|---|---|---|---|
| 앱 전면·잠금 해제 | 필수 | 필수 | 필수 |
| 앱 백그라운드·잠금 해제 | 해당 없음 | 필수 | 필수 |
| 앱 프로세스 미실행·잠금 해제 | 앱 실행 후 | 필수 | 필수 |

| 잠금·화면 꺼짐 | 해당 없음 | 가능한 시스템 진입점 확인 | 필수 |

위젯·액션 버튼 등을 채택하면 별도 열과 지원 기종 조건을 추가한다. 잠금 상태 오류나 시스템 미호출을 앱 저장 실패와 구분한다. 실기기 없는 검증은 NOT RUN이며 자동 통과 처리하지 않는다.

## 출시 준비

- Apple Developer 계정, Bundle ID, 서명, capabilities, 배포 대상·사용 SDK를 실제 환경에 맞게 확정한다.
- Release 빌드 및 TestFlight 설치에서 앱·Intent·뒷면 탭·설정·데이터 보존을 재확인한다.
- 앱 이름·아이콘·스크린샷·설명·지원 URL·개인정보처리방침 URL과 앱 내 접근 경로를 준비한다. [S07]
- 로컬 데이터, 기기 백업, 삭제·보관 정책, 실제 포함 SDK의 전송을 검토해 App Privacy 응답을 작성한다. 무수집으로 자동 체크하지 않는다. [S08]
- 실제 사용 API·SDK에 해당하는 privacy manifest와 required-reason API 신고 필요성을 현재 Apple 문서로 확인한다. [S09]
- 심사 메모에 단축어 액션 위치와 뒷면 탭 수동 연결, 시험 가능한 단계, 지원 제약을 설명한다.
- 출시 정책 질문을 해결하고 P0/P1을 닫는다. 미해결 제한은 지원 범위·설명·테스트에 일치시킨다.

## 완료 게이트

개발 완료: 기능·자동 테스트·디자인 확인 완료. 검증 완료: 독립 검증과 핵심 실기기 증거 확보. 제출 준비 완료: 메타데이터·개인정보·서명·Release 확인 완료. 배포 완료: 실제 App Store 배포 확인. 네 단계를 서로 대체하지 않는다.
