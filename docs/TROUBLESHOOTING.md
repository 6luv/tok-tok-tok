# 트러블슈팅 기록

아래 '이슈 기록'은 개발 중 실제로 관측한 문제다. '초기 진단 가이드'는 관측 결과가 아니다.

## 기록 템플릿

이슈 ID / 발견일 / 담당 / 상태(open·investigating·fixed·verified):

영향받는 요구사항·테스트 / 기종·OS·앱 버전 / 실행 경로 / 잠금·화면·프로세스 상태:

재현 단계 / 기대 결과 / 실제 결과 / 재현 빈도 / 비식별 증거:

가설 / 확인 방법 / 관측 결과 / 확인된 원인:

시도한 수정과 실패 이유 / 최종 변경 / 데이터 영향 / 수정 커밋:

회귀 테스트 / 독립 재검증 담당·날짜·결과 / 남은 제한:

추측을 원인으로 확정하지 않는다. ‘재현 안 됨’과 ‘수정됨’을 구분한다.

## 초기 진단 가이드

| 증상 | 확인 순서 |
|---|---|
| 뒷면 탭으로 기록 없음 | 단축어 직접 실행 → 수동 연결 확인 → 기종·OS·잠금·화면 상태 → Intent 진입 여부 → 저장 결과 |
| 단축어 액션이 안 보임 | 빌드의 App Intents 메타데이터·타깃 포함 → 설치 버전·액션 이름 → 초기 앱 설정 → 재설치 전 데이터 보존 |
| 잠금에서만 실패 | 인증 정책 → OS 실행 제한 → Data Protection·최초 잠금 해제 여부 → 저장 오류; 데이터 보호를 임의로 낮추지 않음 |
| 성공 안내 뒤 기록 없음 | 실제 save 완료 시점 → UI/Intent 저장 경로·스키마 → 조회 구간·시간대 → UI 갱신 |
| 기록이 다른 날에 있음 | 사용자 경계·현재 시간대 → [시작, 다음 시작) → DST → 설정 변경 정책 |
| 기록 중복 | 별도 사용자 실행인지 → Intent 재호출인지 → 내부 재시도 ID인지 구분 |
| 재실행 시 기록 사라짐 | 메모리 저장소 사용 여부 → 컨테이너 경로 → 마이그레이션 실패·초기화 코드 |
| 백그라운드 햅틱 없음 | 지원 실행 환경 확인; 햅틱 부재를 저장 실패 또는 성공으로 판단하지 않음 |

데이터를 삭제해 증상을 없애는 조치는 복구로 간주하지 않는다. 파괴적 조치가 필요하면 데이터 영향과 복구 가능성을 먼저 기록하고 사용자 승인을 받는다.

## 이슈 기록

### TS-001 개발 환경에 Xcode 없음 / 원격 저장소 인증 불가

- 발견일: 2026-10-31 / 담당: Claude / 상태: open(환경 제약)
- 관측: 연결된 Mac의 명령 실행 환경은 Linux VM(aarch64)이며 `xcodebuild`·`swift` 없음. 클라우드 작업 공간(Ubuntu 24.04)에도 Xcode 없음. `git ls-remote origin`은 `could not read Username for 'https://github.com'`로 실패.
- 조치: 플랫폼 독립 로직을 TokTokCore Swift 패키지로 분리하고 Linux용 Swift 6.4.1을 설치해 `swift test`로 검증. iOS 앱 타깃(App Intent·SwiftUI)은 컴파일하지 못했으므로 사용자 Mac의 Xcode에서 빌드·실기기 실행이 필요.
- 화면 제어(computer use)로 Xcode를 조작하는 방안은 macOS 화면 기록 권한 미부여 상태였고, 사용자가 시뮬레이터 대신 실기기로 확인하기로 해 사용하지 않음.
- 원격 fetch/push는 하지 않았다. 브랜치 비교는 로컬 브랜치 기준.

### TS-002 테스트 입력의 소수 초 ISO8601 파싱 실패 (테스트 코드 결함)

- 발견일: 2026-10-31 / 상태: fixed
- 재현: `swift test` 중 `StorageAndServiceTests.swift:18: Fatal error: Unexpectedly found nil` (signal 4)
- 원인: 기본 `ISO8601DateFormatter`는 `.123Z` 소수 초를 파싱하지 않음. 제품 코드 문제 아님.
- 수정: 테스트에서 정수 초 문자열 + `addingTimeInterval(0.123456)`으로 입력 생성. 재실행 28건 통과.

### TS-003 Swift 6 동시성 경고(테스트 코드)

- 발견일: 2026-10-31 / 상태: fixed
- 관측: `@Sendable` 시계 클로저가 가변 지역 변수를 캡처해 "Swift 6 language mode에서는 오류" 경고.
- 수정: 잠금을 가진 `MutableClock` 테스트 도우미로 교체. 경고 0건 확인.

### TS-004 블록 구분선 대비 낮음 (관찰)

- 발견일: 2026-10-31 / 상태: open / 심각도 제안: P3
- 관측: DESIGN 토큰 구분선 #343438과 블록 #1C1C1F의 대비 1.37:1(계산값).
- 영향: 텍스트 가독성 문제는 아님. 블록 사이 경계가 어둡게 보일 수 있음.
- 조치: 디자인 결정 대기. 실기기에서 실제로 구분이 어려우면 구분선 색 조정 검토.
- 2026-11-10 갱신(feature/ui-redesign): 구분선을 본문색 8% 가는 선으로 바꿔 면 대비 1.23:1(계산값). 블록 면 #19191B와 바탕 #0F0F10의 단계 차이가 목록 경계를 보완한다. 시뮬레이터 스크린숏에서는 블록 사이 선이 보였다. 실기기 확인 전까지 open 유지.

### TS-005 앱 타깃 코드 미컴파일 (확인 필요)

- 발견일: 2026-10-31 / 상태: 부분 해소 — 2026-10-31 사용자가 feature/day-screen을 iPhone에서 실행 확인했다고 보고(빌드 로그·기기 정보 미기록). 이후 브랜치(feature/back-tap-setup)의 변경은 다시 미컴파일
- 내용: TokTok 앱 타깃(SwiftUI·App Intents)과 TokTokTests는 이 세션에서 컴파일하지 못했다(TS-001). 공식 문서에서 확인한 API만 사용했지만 첫 Xcode 빌드에서 컴파일 오류가 날 수 있다.
- 다음 단계: 사용자 Mac에서 `xcodebuild -project TokTok.xcodeproj -scheme TokTok -destination 'generic/platform=iOS' build` 또는 Xcode에서 실기기로 Run. 오류 로그를 이 항목에 기록하고 수정 커밋을 연결한다.

### TS-006 앱에서 뒷면 탭 설정을 자동으로 연결할 수 없음 (플랫폼 제약)

- 발견일: 2026-10-31 / 상태: 제약으로 확정(우회하지 않음)
- 요청: 뒷면 탭과 단축어 연결을 앱이 대신 해 주기.
- 확인: 손쉬운 사용 > 뒷면 탭 설정을 여는 공개 URL이나 값을 바꾸는 공개 API가 없다(PRD §6, CLAUDE 구현 제약). 공개 문서로 확인한 것은 `ShortcutsLink`(iOS 16+, 단축어 앱의 앱 페이지 열기)와 `shortcuts://create-shortcut`(새 단축어 편집기) 뿐이다.
- 조치: 연결 도우미 화면에서 단축어 앱 이동 버튼 2개, 설정 경로 단계 안내, 마지막 단축어 기록 시각 표시로 사용자가 직접 연결을 확인하게 함. 비공개 설정 URL은 쓰지 않음.
- 남은 확인: 뒷면 탭 단축어 목록에 App Shortcut이 바로 보이는지, 사용자가 만든 단축어만 보이는지는 실기기에서 확인 필요(안내는 사용자 단축어를 만드는 쪽으로 작성).

### TS-007 화면이 꺼진 상태에서 뒷면 탭으로 기록되지 않음

- 발견일: 2026-10-31 / 보고: 사용자 실기기(기종·iOS 버전 미기록) / 상태: closed(2026-11-11, 지원 범위를 화면 켜짐으로 제한) — 원인은 플랫폼 제약으로 추정
- 관측(사용자 보고): 뒷면 탭 → 단축어 → 기록은 화면이 켜진 상태에서 성공. 화면이 꺼진 상태에서는 기록되지 않음.
- 가설: 화면이 꺼져 있으면 iOS가 뒷면 탭 제스처를 처리하지 않아 단축어·App Intent가 호출되지 않는다. 앱의 저장 실패라면 단축어가 “기록되지 않았어요” 오류를 보여야 하는데, 그런 보고는 없다.
- 미확인: Apple 공식 문서에서 화면 꺼짐 동작을 명시한 근거는 찾지 못했다. 원인을 확정하지 않는다.
- 확인 방법(다음 실기기 시험):
  1. 화면 켜짐 + 잠금 상태(잠금 화면이 보이는 상태)에서 뒷면 탭 → 기록 여부. 성공하면 잠금·파일 보호는 문제가 아니고 화면 꺼짐에서 트리거가 오지 않는 것으로 좁혀진다.
  2. 화면 꺼짐에서 뒷면 탭 후 화면을 켰을 때 단축어 오류 알림이 있는지.
  3. 화면 꺼짐·잠금 상태에서 Siri로 실행 → 기록 여부.
- 앱 측 조치: 앱 코드로 iOS의 뒷면 탭 인식 조건을 바꿀 수 없다. 데이터 보호를 낮추거나 백그라운드 모드·센서 감시로 우회하지 않는다(CLAUDE 구현 제약). 앱 안내 문구에 화면 꺼짐 제약과 Siri 대안을 표시했다.
- 제품 영향: 핵심 사용 장면(자다 깸, 화면 안 켬)을 뒷면 탭만으로는 충족하지 못할 수 있음 → Q10 결정 필요. 후보: Siri 음성, 잠금 화면 컨트롤(iOS 18+, 화면을 깨워 한 번 누름; 액션 버튼 기종은 버튼으로 실행).
- 후속(2026-11-11): 사용자 실기기에서 잠금 상태 Siri 실행도 되지 않음(사용자 보고, 기종·iOS 미기록). **Q10 사용자 결정:** 뒷면 탭 기록은 화면이 켜진 상태에서만 지원한다. 앱(설정 연결 카드 꼬리말, 연결 화면 ‘알아 두세요’)·지원 페이지에 ‘화면이 켜져 있을 때만’을 안내하고, 위 조치의 Siri 대안 안내는 제거했다(fix/screen-on-only, R-039). App Shortcut 문구(`TokTokShortcuts.phrases`)는 단축어 앱 노출에 필요해 남겼으므로 잠금 해제 상태의 Siri 호출 자체는 막지 않는다. 잠금 화면 컨트롤 등 다른 대체 수단은 범위 밖. 상태: closed — 지원 범위 제한으로 결정(원인은 여전히 플랫폼 제약 추정)
